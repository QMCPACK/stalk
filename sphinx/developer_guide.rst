Developer guide
===============

This guide summarises internal design and where to look when extending or
modifying STALK.

Architecture overview
---------------------

- ``io`` — File I/O for PES and geometry formats (see :doc:`api`).
- ``ls`` — Core line-search algorithm types: fitting functions, settings and results.
  The `LineSearch` abstractions live here.
- ``pls`` — Parallel/ensemble orchestration. The ``Surrogate`` class implements
  the accelerated parallel line-search algorithm and is the main entry point for
  target-parallel optimisation.
- ``lsi`` — Iteration-level helpers and pathway imaging utilities used by
  higher-level drivers.
- ``params`` — Parameter abstractions (lengths, angles, phases), PES wrappers
  and mapping utilities useful when adapting STALK to different molecule
  representations.
- ``nexus`` — Optional integration glue for running external codes through Nexus.

Developer notes
---------------

- Public API is exported from the package top-level in ``stalk/__init__.py``.
- Add new public classes to the top-level exports for convenience, and update
  ``__all__`` accordingly.
- Tests live under the ``tests/`` directory; add unit and integration tests for
  new features.
- Use existing style and docstring conventions; API docs are generated by
  Sphinx ``autodoc`` from module docstrings.

Regenerating API docs
---------------------

From the project root, you can (locally) regenerate API stubs and build the
HTML docs:

.. code-block:: bash

   # build docs
   cd sphinx
   make html
